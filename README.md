# CRM фонда «Люди и Верблюды» — 0.11.3

Версия 0.11.3 исправляет найденные при аудите проблемы безопасности и стабильности и продолжает интеграцию унифицированных Contact Form 7 и приводит базовые административные операции CRM к единому интерфейсу. Релиз устанавливается поверх того же плагина `lv-applications/`.

## Единый контракт форм

CRM принимает публичные заявки только через зарегистрированные стабильные контракты:

- `need_help` — «Нужна помощь»;
- `support_contact` — «Поддержать»;
- `volunteer_application` — «Волонтёр».

Общие идентификаторы:

- `form_code`;
- `form_schema_version`;
- `contact_name`;
- `contact_phone`;
- `contact_email`;
- `message`;
- `consent_personal_data`;
- `consent_newsletter`;
- `consent_pd_version`;
- `consent_marketing_version`.

Специализированные поля остаются частью конкретного контракта формы. CRM не содержит слоя совместимости со старыми формами и не распознаёт имя, телефон, e-mail и другие значения по альтернативным названиям полей или эвристикам. Неизвестный `form_code` либо неподдерживаемая версия схемы сохраняют заявку, но автоматическая синхронизация контакта для неё не выполняется.

Канонические `form_code` и `form_schema_version` читаются из серверного шаблона Contact Form 7; значения из браузера используются только для проверки расхождений.

Каждая новая отправка получает серверный `submission_uuid`.

## Контакты из форм

Для поддерживаемого контракта CRM:

1. нормализует телефон и e-mail;
2. ищет существующий активный контакт;
3. связывает заявку при однозначном совпадении;
4. создаёт контакт, если совпадений нет;
5. не выполняет автоматическое слияние, если телефон/e-mail указывают на разные карточки;
6. безопасно дополняет контакт структурированными полями;
7. применяет системные метки «Волонтер» / «Донор» по правилам формы;
8. фиксирует согласия и источник их получения.

## Согласия

Поддерживаются контактные согласия:

- `personal_data` — обработка персональных данных;
- `marketing` — информационные и рекламные сообщения.

Для события сохраняются статус, дата, источник, заявка, версия документа, каналы, `form_code`, версия схемы, `submission_uuid`, URL, IP, User-Agent и доказательство. Непоставленный необязательный чекбокс рассылки не считается отзывом ранее предоставленного согласия.

E-mail-уровень маркетингового статуса используется как слой контроля безопасного рассылочного экспорта.

## 0.11.3 — безопасность и стабильность

- ограничена видимость контактов для Авторов/Участников: доступны только созданные ими, курируемые либо связанные с доступными им заявками контакты;
- закрыты прямые обходы ACL через карточку контакта, AJAX-поиск и ручную привязку контакта;
- CSV-экспорт заявок защищён от spreadsheet/formula injection;
- новые вложения заявок по умолчанию сохраняются вне обычного web-root, при этом старое хранилище остаётся доступно для чтения после обновления;
- контракт формы «Волонтёр» теперь, как и остальные публичные формы, требует `contact_phone`;
- добавлена автоматическая проверка синтаксиса PHP в GitHub Actions.

## 0.11.2 — управление и удобство

### Заявки

- исправлен возврат после одиночного перемещения заявки в корзину;
- массовые действия вынесены в заметную липкую панель, которая появляется только после выбора записей;
- массово доступны существующие операции: статус обработки, приоритет, ответственный, метки, корзина, восстановление и окончательное удаление;
- можно выбрать текущую страницу либо все записи, соответствующие фильтрам;
- после мягкого удаления доступна отмена в течение 10 минут;
- контекст списка сохраняется при открытии карточки: фильтры, сортировка, страница и размер страницы;
- в карточке доступны переходы «Предыдущая / Следующая» в пределах текущей выборки;
- размер страницы: 25 / 50 / 100;
- выбранные строки подсвечиваются, панель выбора остаётся доступной при прокрутке;
- массовые операции показывают количество выбранных, изменённых и пропущенных записей.

### Контакты

- единая корзина с восстановлением и окончательным удалением;
- массовое назначение куратора, добавление/снятие меток и операции корзины;
- выбор всех контактов по текущим фильтрам;
- сортировка списка по доступным колонкам;
- размер страницы: 25 / 50 / 100;
- сохранение контекста при переходе в карточку;
- переходы «Предыдущий / Следующий» в пределах текущей выборки;
- отмена мягкого удаления;
- защита формы от случайного ухода с несохранёнными изменениями и двойной отправки;
- явное уведомление после сохранения контакта.

### Метки

- существующие метки можно редактировать;
- перед удалением показывается количество использований в контактах и заявках;
- технический slug системной метки при обычном редактировании не меняется;
- системные метки `volunteer` и `donor` нельзя удалить или перевести в область «только заявки», чтобы автоматизация форм не могла быть случайно сломана.

## Обновление

Каталог и главный файл плагина не изменены:

- `lv-applications/`;
- `lv-applications/lv-applications.php`.

Перед установкой обновления рекомендуется сделать резервную копию базы данных. После обновления нужно проверить по одной тестовой отправке каждой из трёх унифицированных форм и основные операции корзины/массового управления.

## Требования

- WordPress 6.2+;
- PHP 7.4+;
- PHP-расширение `ZipArchive` (`ext-zip`) для XLSX-экспорта;
- Contact Form 7 для приёма публичных заявок.
